0. 怎么用这份稿

三版是三种布局骨架（layout skeleton），不是换配色：配色统一沿用现在的深色方案 A（底 #242424 · 面 #2f2f2f · 强调 #6cc9ff）， 只改结构、层级、字号、留白，这样你能单独判断「布局好不好看」。 看完直接回我一个字母（A / B / C）或组合（例如「A 的骨架 + C 的表格」），我再按选定方案改 app/ 代码。
方案布局取向最适合的场景
A 左列表 + 右详情主从布局（master-detail）：左边一列结果，右边看大图与详情知道车型，要一个明确的支架号和图，逐条看
B 图卡网格画廊布局（gallery / card grid）：图大、号大、一屏 4 个不知道编号，靠肉眼比形状选件
C 数据台表格数据台（data desk）：表格为主，字号行高拉开，列重排批量核对、复制编号、报给客户，一屏看最多条

设计要点

区域规范
标题区18～20px 标题 + 计数（数字 16px accent 等宽），替换现在的 14px「按车型查支架　model → bracket」
筛选条单行 12px 字段，右侧分段控件 + 列设置；总高 44（现在两层共 64）
表头11px 弱化色、sticky、无竖线；行高 38，斑马纹从中灰降到 #282828
列序缩略图 → 支架号（等宽加粗）→ 车型 → 年款区间（chip）→ 年款原文（弱化）→ 来源（圆点）→ 操作
操作双击行 = 反查；右键菜单 = 复制编号 / 复制整行；键盘可全选复制
优点：改动最集中（models.py 列定义 + theme.py QSS + ui.py 表头），风险最低；一屏 16 行，批量核对最快；不做图像排版，天然不会"花"。
缺点 / 风险：图片缩到 36px 就只能认"大概是哪种"，靠图选件不行；"好看"的提升主要靠字号/行高/留白，仍然是表格型工具，观感偏工程化。

7. 实现影响面与风险

文件ABC
app/ui.py重写 Page 骨架 + 列表项组件新增卡片网格组件只调表头与间距
app/pages/model_page.py重写（左列表 + 详情）重写（网格 + 选中条）改列定义与空态
app/pages/bracket_page.py部分复用右详情复用卡片网格改列定义
app/theme.py+约 60 行 QSS+约 80 行 QSS+约 40 行 QSS
app/main.pyTab → 分段控件（QStackedWidget）同 + 居中搜索栏筛选条合并
app/db.py / models.py不改 SQL、不改 Repository 接口（三版都只用现有 7 个方法）
技术约束（必须提前知道）：PySide6 的 QSS 只支持 CSS 2.1 子集 —— 没有 flex / grid / box-shadow / transition。 A 的左右分栏要用 QSplitter 或定宽 + QHBoxLayout；B 的卡片网格要用 QListView(IconMode) + 自定义 delegate（或手写 FlowLayout）； C 的 chip 与圆点要用自定义 QStyledItemDelegate 绘制，否则只能用文字色区分。这些都只是工作量，不是做不到。

8. 建议与待拍板

我的建议：A 的骨架 + C 的表格细节。即左侧支架列表（大图预览在右），右侧详情下方那块表用 C 的行高 38 / chip 年款 / 圆点来源。 理由：这个工具的日常动作是「报一个准确的支架号」，A 把"看图 + 抄号"压到一屏一次点击；而批量核对时 C 的表格密度更实用，两者可以共存于同一页。 B 最漂亮，但只在"看形状猜型号"这一种场景赢，且实现风险最高，建议作为第二阶段（等 A/C 稳定后再加"图册视图"切换）。
