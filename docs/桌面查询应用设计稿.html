v1.0 · 2026-10-24 · 数据源 scraper/data/ky.db（300 支架 / 269 品牌 / 1,479 车型 / 6,091 条适配关系 / 568 张图片）

状态：未落地（not implemented）。本稿仅为界面与功能设计预览，未写任何应用代码、未安装任何依赖。窗口内数据为真实抓取样本（sample data）。

1 · 设计目标与定位（Goals）

把已抓取的支架适配数据变成一台离线、可批量、可反查的桌面查询工具（desktop query tool）。核心用户：修理厂师傅、配件销售、电商客服。

  • 离线可用（offline-first）：直读本地 SQLite，不依赖站点（站点随时可能改版/关停）。
  • 查询为主（query-centric）：不做增删改，界面 90% 面积服务于查询与结果。
  • 多维入口（multi-dimension）：同一份数据提供 6 个查询维度，覆盖「知道车型」「知道支架号」「只知道年份」「看图选号」等真实场景。
  • 可信标注（provenance）：每条结果标注来源（A 路 / B 路）与校验状态（A 路反查存在 59 条缺口）。

3 · 六个查询维度（Six Query Dimensions）

#维度典型问法输入 → 输出 / 实现要点
Q1 按车型查支架
model → bracket		 「一汽奥迪A4L 2018 款用几号支架？」 输入：品牌 + 车型（模糊搜索）+ 可选年款
输出：支架号卡片（大图 + 号 + 年款区间 + 来源标记）
要点：主用 source='B'（车型页权威），缺失时补 'A' 并标「仅反查有」
Q2 按支架查车型
bracket → models		 「141 号支架都能装哪些车？」 输入：支架号（下拉/图册点选）+ 品牌筛选
输出：车型清单（品牌/车型/年款）+ 命中计数
要点：source='A' 为主；用于备货与库存场景
Q3 按年款区间查
year range		 「2015–2020 年的奥迪有哪些适配记录？」 输入：起止年份 + 可选品牌/支架号
输出：车型-支架对照表
要点：区间重叠判定 year_from<=:end AND year_to>=:start；「全系」(year IS NULL) 单独开关
Q4 品牌覆盖分析
brand coverage		 「哪些车型还没适配数据？」 输入：品牌（可全选）
输出：KPI（车型数/有适配数/覆盖率/支架覆盖数）+ 缺口清单
要点：models LEFT JOIN fitments 求差集；用于发现数据缺口与补录
Q5 数据差异查询
data diff		 「哪些记录两路对不上？」 输入：状态筛选 ONLY_A / ONLY_B / MATCH / CONFLICT
输出：差异清单 + 双路支架号对照 + 一键导出 CSV
要点：直读 crosscheck；ONLY_B（59 条）即站点反向索引缺失的真实证据，ONLY_A 多为「全部年款」口径差异
Q6 支架图册
visual browse		 「师傅手里有个支架，看图认号」 输入：翻页/号段筛选/关键字
输出：4×N 大图网格（图 + 编号 + 适配车型数）
要点：点图直达 Q2 反查；缩略图需预生成（见 §9 风险）
第 7 个入口：全局搜索（global search）——顶部搜索框跨「品牌 / 车型 / 支架号」模糊匹配（fuzzy match），命中后自动跳转到对应维度 Tab，解决「不知道该用哪个维度」的起步问题。

交互约束（interaction rules）

  • 最小窗口 1024×680：小于此宽度时左侧筛选面板折叠为下拉。
  • 查询响应 < 100ms：SQLite 本地查询，结果 > 500 行时分页（每页 200）。
  • 所有维度支持导出 CSV：UTF-8 BOM，列名与字段名一致。
  • 键盘优先：Ctrl+K 聚焦搜索；↑↓ 切换列表项；Enter 查询。

8 · 数据层与 SQL（Data Layer）

应用以只读方式打开 ky.db（sqlite3.connect(path, mode=ro) 或 URI file:...?mode=ro），与爬虫进程互不干扰（配合 WAL）。

Q1 按车型查支架

SELECT bracket_id, years_raw, year_from, year_to, years_json, source
FROM fitments
WHERE brand = ? AND model LIKE ?
ORDER BY source DESC, year_from;          -- B 路优先（车型页权威）

Q2 按支架查车型

SELECT brand, model, years_raw, year_from, year_to
FROM fitments WHERE source = 'A' AND bracket_id = ?
ORDER BY brand, model;

Q3 年款区间重叠

SELECT brand, model, bracket_id, years_raw
FROM fitments
WHERE year_from IS NOT NULL AND year_from <= :end AND year_to >= :start
  AND (:brand IS NULL OR brand = :brand);      -- 「全系」(NULL) 由开关单独纳入

Q4 品牌覆盖缺口

SELECT m.brand, m.model FROM models m
LEFT JOIN fitments f ON f.brand = m.brand AND f.model = m.model
WHERE f.id IS NULL AND m.brand = :brand;

Q5 数据差异

SELECT brand, model, year, bracket_a, bracket_b, status
FROM crosscheck WHERE status = :status ORDER BY brand, model;
建议新增索引（index）：现有 idx_fit_brand_model 已覆盖 Q1/Q4；Q2/Q3 建议补 (source, bracket_id) 与 (year_from, year_to)。6,091 行数据量下不加也能跑，但加索引可让图册与区间查询更稳。

9 · 实施步骤与风险（Plan & Risks）

实施步骤（proposed steps）

  1. 确认技术选型 → 安装依赖（方案 A 仅需 pip install PySide6）。
  2. 数据层 db.py：只读连接 + 6 个查询函数（对应 Q1–Q6）+ 字典缓存（品牌/车型/支架号一次性载入）。
  3. 主窗口骨架：标题栏 + 工具栏（搜索 + 6 Tab）+ 左筛选 + 主结果区 + 状态栏。
  4. 逐 Tab 实现：Q1 → Q2 → Q6 → Q3 → Q4 → Q5（按使用频率排序）。
  5. 导出 CSV、键盘快捷键、空态与异常态。
  6. 打包（可选）：PyInstaller 单文件 exe；工作日志与 README 同步。

风险与缓解（risks）

风险影响缓解措施
图册加载 299 张大图卡顿Q6 首屏慢（原图单张可能数百 KB）启动时生成缩略图缓存（data/thumbs/，160×120），或按需懒加载 + 异步
A 路反向索引缺口 59 条（0.61%）影响面很小，但仍会让个别车型「查不到」Q2 顶部常驻提示「以按车型查为准」，并联动 Q5 显示差异数

数据库被爬虫重写时读取冲突应用查询报错只读模式 + WAL；应用启动记录数据时间戳，变更时提示「数据已更新，点击刷新」
