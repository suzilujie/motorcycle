查询结果就地编辑 · 设计稿 v1.0

项目 KYBracket · 2026-10-26 · 范围：按支架查 + 按车型查的结果表格就地改 + 行删除 · 未提交未构建

一句话：把两个查询页右侧的只读表格变成「双击即改、改完立即写库」，并给每行加删除入口；所有写操作沿用现有 backup_database() 先备份再提交。

1. 现状与目标

项现状目标
结果表格QTableView 只读，DictTableModel.flags() 不返回 ItemIsEditable品牌 / 车型 / 年款原文三列可编辑
写库能力db.py 只有 add_manual()新增 update_fitment() / delete_fitment()
行标识两个查询 SQL 都没 SELECT id补 id 字段（不显示，仅供写回定位）
删除入口无行末「删除」链接 + Delete 键 + 右键菜单，三处一致
防误操作—删除二次确认；编辑保存前校验年款；每次写前自动备份

2. 交互流程

2.1 编辑

双击单元格（或选中后按 F2 / 直接敲字）
  → 单元格变成内嵌输入框，原值预填、全选
  → 回车 / 失焦 = 提交    Esc = 取消
  → 校验
       品牌/车型：不能为空
       年款原文：交给 years.parse_years()，失败直接拒绝
  → 通过：UPDATE fitments SET … WHERE id = ?（先 backup_database()）
    失败：输入框变红 + 表格下方红条提示，值回滚成原值，不写库
  → 成功：重新执行当前查询 + 刷新品牌/车型字典 + 状态栏提示

2.2 删除

选中一行 → 点行末「删除」/ 按 Delete / 右键「删除这一行」
  → 弹确认框，列出 支架号 + 品牌 + 车型 + 年款原文
  → 确认：DELETE FROM fitments WHERE id = ?（先 backup_database()）
  → 成功：重新查询 + 刷新统计
  → 取消：什么都不做

2.3 可编辑列

列可编辑说明
品牌 brand是改完同步 INSERT OR IGNORE 进 brands / models
车型 model是同上
年款区间 range否派生列，由 year_from / year_to 算出，改年款原文后自动重算
年款原文 years_raw是提交时重新解析 year_from / year_to / years_json
来源 source否A = 抓取，M = 手工，不应被改

5. 数据与安全

  • 每次 update_fitment() / delete_fitment() 之前调用 backup_database()，与 add_manual() 完全一致；BACKUP_KEEP = 10 自动滚动清理。
  • 写操作走 write_connection() 单事务，异常整笔回滚（不会出现改一半）。
  • 改品牌 / 车型时同步 INSERT OR IGNORE 进 brands 与 models，避免出现「有 fitment 但字典里没有该车型」。
  • 删除只删 fitments 一行，不动 brackets / brands / models。
  • 数据库当前是只读连接（connect_readonly()）供查询；写入另开 write_connection()，写完 repo.reload() 清缓存。

7. 风险

风险等级对策
误改误删生产数据高每次写前自动备份（10 份滚动）；删除二次确认；明细可读回备份
改品牌/车型导致记录脱离当前查询中写成功后重跑当前查询，行会自然消失并提示「已移出当前条件」
年款解析失败写入脏数据中复用 years.parse_years()，失败直接拒绝并回滚显示
编辑中途切换页面丢失修改低提交后才算完成；未提交直接丢弃（不缓存草稿）
大量行时逐行备份体积膨胀低备份上限 10 份，单库 2.9 MB，总量 < 30 MB
