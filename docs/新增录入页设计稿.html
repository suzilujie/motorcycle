1. 版本变化

点v1（旧稿）v4（本稿）
结构一张主表单混录「品牌+车型+支架」两个独立模式：新增车型 / 新增支架，页内胶囊切换
关系录入一次只能挂 1 个支架新增车型 → 可勾选多个支架；新增支架 → 可勾选多个车型
年款整张表单一个年款左栏一个统一年款框，作用到本批全部选中项；默认留空 = 全部年款
保存结果1 条适配记录N 条适配记录（N = 勾选数量），逐条去重，返回「成功 N / 跳过 M」
快捷入口另有「只新增车型」「只新增支架」两个小卡不再需要：不勾任何一项即等于「只建档」
已选面板无固定宽 250，每条一行：标识 + 该条最终写入的年款 + 移除

已撤销：逐条年款（per-row year）

尝试过的 v3 方案为什么撤销
已选面板每条两行 + 独立年款输入框面板从 250 撑到 300+，每条两行 + 解析 chip + 行内红字校验，交互过重，录入一个支架要先切 4 次年款框
逐条即时校验 + 保存按钮置灰为了少数「年款确实不同」的场景，给所有录入加了成本，得不偿失
结论：年款差异不靠界面解决，靠「默认留空」解决。录入新车型/新支架时，年款信息本身往往还没核实清楚， 留空（= 全部年款）才是安全默认；真的需要精确年款时，只在少数条目上单独补录。界面不为 10% 的场景付 100% 的复杂度。
为什么两个模式分开仍然成立：两个方向的信息量本来就不对称——「这台新车能装哪几个支架」通常一次能说出 2~3 个； 「这个新支架适配哪些车」往往要勾一串车型。把两者塞进一张表单，必然一边要反复提交。

4. 多选控件规范

元素规范
候选列表每行 30px；左起 12px 复选框 → 主标识（支架号 / 品牌+车型）→ 缩略图或年款 → 右侧弱化元信息；未选无底色，选中行左侧不加条只换复选框（避免与主列表选中态混淆）
搜索框复用全局拼音逻辑（全拼 / 首字母 / 中英混输），只过滤候选列表，不影响已选
已选面板固定宽 250；每条一行：主标识 + 年款 + 「移除」；标题右侧显示数量；数量为 0 时整块显示「未选择 = 只建档，不生成适配记录」
年款框左栏一个输入框 + 右侧 chip 实时回显解析结果（全部 / 2024 – 2026）；非法值输入框描边转红，不弹窗
批量操作「全选筛选结果」只作用于当前过滤后的候选；「清空已选」一键清空
保存按钮文案带数量：保存（3 条）；数量为 0 时变保存（仅建档）；存在非法年款时置灰
键盘候选列表支持 ↑↓ 移动、空格勾选、Ctrl+A 全选当前筛选结果

5. 校验与保存语义

场景行为
品牌 / 车型 / 支架号 不存在自动创建，输入框右侧 chip 显示「将新建」（蓝）；已存在显示「已存在」（灰）
年款一个统一值作用到本次全部选中项；默认留空 = 全部年款（year_from / year_to 写 NULL）；越界年份（<1980 / >2035）输入框标红并置灰保存
重复组合库里已有 (source='M', 支架号, 品牌, 车型, 年款原文) → 跳过，计入「跳过 M 条」，不报错不覆盖
保存结果绿字：成功 3 条 · 跳过 1 条（已存在）；表单不清空、已选保留，方便在同批基础上续加
事务品牌/车型/支架/适配 全部在一个事务里；任一步失败整批回滚，不会留半个对象
保存前自动备份 ky.db → data/backup/ky-YYYYmmdd-HHMMSS.db（保留最近 10 份）

6. 数据落库

已核对 scraper/store.py：建表均为 CREATE TABLE IF NOT EXISTS、写入为 INSERT OR IGNORE， 仅 crosscheck 会被 DELETE 后重建 → 手工写入同一 ky.db 不会被重爬清掉。

动作SQL（示意）
新增车型模式INSERT OR IGNORE brands / models →
对每个选中支架：INSERT OR IGNORE fitments(source='M', bracket_id, brand, model, years_raw, year_from, year_to, years_json, fetched_at)
新增支架模式INSERT OR IGNORE brackets(bracket_id, image_file, updated_at) →
对每个选中车型：INSERT OR IGNORE fitments(source='M', …)
判重键（已核对 schema）UNIQUE (source, bracket_id, brand, model, years_raw) —— 年款不同即视为不同记录
NULL 判重坑SQLite 的 UNIQUE 认为 NULL 互不相等 → 「留空年款」若写成 years_raw = NULL，同一条重复录入拦不住，会插重复行。手工录入的空年款必须存空串 ''（year_from / year_to 仍可为 NULL）
来源标记fitments.source = 'M'；界面用紫色圆点区分，crosscheck 统计天然不含 M
只读边界db.connect_readonly()（mode=ro）完全不动；新增 db.write_connection() 短开短关
需放宽的查询Q2 bracket_models：source='A' → source IN ('A','M')，否则新录入的支架查不到自己

与设计稿的偏差（实现时按实际技术约束调整）

点设计稿实现
年款解析位置写在 db.py独立 app/years.py：UI 每次击键都要校验，放在 db 层会绕成反向依赖
M 来源圆点颜色紫色橙黄（warn）：A 路本来就用紫色 #a78bfa，再用紫色会撞色分不清
已选面板移除每行一个「移除」「移除选中」按钮 + 双击移除：QListWidget 原生即支持，省 200 行自定义行控件
最近录入表批次汇总（「N 个支架」）按 fitment 行展示（支架号/品牌/车型/年款/来源/时间）：没有批次表就不硬造聚合口径
候选列表无明显上限说明无关键词时只显示前 200 条并在标题旁注明，关键词可搜全库
app/search.py加 clear_cache()未改：拼音键缓存以文本为 key，新词首次出现时自然重算，加 clear 是死代码
风险缓解
写坏库（无 git，库是唯一数据源）每次保存前自动备份到 data/backup/，保留 10 份；整批事务
一批勾太多误提交按钮带条数 + 保存后「成功/跳过」明确回执；不做自动清空，可立刻二次核对
与爬虫并发写写连接 timeout=15；爬虫运行时录入可能失败并回滚（有提示，不会写坏）
多选列表卡顿候选上限 200 条（筛选后），1479 车型先按品牌收窄
统一年款填错默认留空（=全部年款）是安全值；已选面板逐条回显将写入的年款，一眼可见；填错后走「按车型查」侧补录正确条目
同组合多年款并存年款不同会落成多行 fitments；反查侧需按 (支架, 车型) 聚合展示年款，否则列表出现重复行 —— 实现时一并确认 Q2 聚合方式
新增支架后仍无适配允许「只建档」但明确提示：该支架在「按支架查」里会显示「暂无反查记录」
