按支架查页「可编辑」设计稿 v1.0

2026-10-28 · 范围：左侧支架卡（图片 + 备注可编辑，支架号只读）+ 车型列表可添加已有车型 · 状态：已实施（v1.1 按用户纠正改为「只选不建」）

1 需求与范围

用户要求：「这个页面要可编辑」。经确认为以下三项，其余保持现状。

项目结论说明
支架图片可编辑本页直接增删多图、点缩略图换封面，复用 ImageStrip
支架备注新增字段brackets 加 note 列，属于支架本身（不是某条适配记录）
支架号只读用户明确「不能改号」；改号要级联 fitments / bracket_images，风险大，不做
车型列表可新增本页为当前支架新增适配记录（source = M），不用回「新增支架」页
表格既有编辑/删除保留行的「编辑 / 删除」链接照旧，不改成就地双击（方案 C 未采用）
设计原则（design principle）：可编辑的东西分两类——支架本身（图 + 备注）走弹窗； 适配记录（品牌 / 车型 / 年款）走行内链接 + 新增弹窗。两者不混在一个表单里， 避免「改了一张图导致整页适配记录被重写」这类连带风险（cascade risk）。

行为规则

品牌下拉「全部品牌」+ 已有品牌；只筛候选，已勾选的车型不因切换品牌而丢失
搜索支持车型 / 品牌关键字与拼音首字母（复用录入页的 CheckList）

写入add_manual(pairs, years_raw)，来源 = M；同支架 / 车型 / 年款已存在则跳过
需要新车型到「新增」页 →「＋ 新增车型」建档后再回来添加

6 数据与接口

6.1 表结构（唯一的破坏性改动）

brackets
  bracket_id TEXT PRIMARY KEY
  image_url  TEXT
  image_file TEXT
  note       TEXT      ← 新增（可空）
  updated_at TEXT

迁移：启动时检查 PRAGMA table_info(brackets)，缺 note 才
      ALTER TABLE brackets ADD COLUMN note TEXT
      （幂等；只在第一次升级触发，触发前先写一份 data/backup/ 快照）
为什么备注放在 brackets 而不是 fitments：一条支架有 14 条适配记录， 备注是「这个支架本身」的属性（比如「右侧进线」）。挂在 fitments 上会重复 14 份， 改一次要写 14 行，撤销也麻烦。

6.2 仓储层（repository）新增方法

Repository.brackets()                     # SELECT 增加 note 列（缓存随 reload() 失效）
Repository.save_bracket_meta(bracket_id, note=None, images=None)
    - 先 backup_database() 再写（与 add_manual 同一策略）
    - 单事务内：更新 note +（images 不为 None 时）复用 _save_bracket 的整表对账
    - note=None 表示「不动备注」，images=None 表示「不动图片」——两个参数互相独立
    - 成功后 self.reload() 清字典缓存

为什么不复用 add_manual()：它必须带 pairs / targets， 语义是「写适配记录」，用它改备注会出现「只想改备注却顺带重算适配」的误解。 但图片对账仍复用它的 _save_bracket()，不重写一套。

6.3 添加车型复用现有写路径

Repository.add_manual(pairs=[(bracket_id, brand, model)…], years_raw=年款)
    → 不传 targets：品牌 / 车型只来自字典，本弹窗不新建任何条目
    → 判重不看 source：同支架 / 车型 / 年款已存在时只回「跳过 1 条」不写重复行
    → source = M，两个查询页照常显示

7 状态与异常

情况行为
老库没有 note 列启动迁移自动补列（先快照）；失败则弹错误并退出，不带病运行
备注超 200 字保存时截断到 200，弹窗内提示「已截断 N 个字」，仍保存成功
选了读不出的图忽略并提示「已忽略 N 张（读不出来或超出上限 6 张）」
删除图片只删 bracket_images 行，磁盘文件保留（与新增页一致，删文件不可逆）
换封面点缩略图移到首位，保存时写回 brackets.image_file
添加车型重复add_manual 判重 → 全部命中时提示「未写入」，不关窗
数据库被爬虫占锁转成「数据库正被别的程序占用，请稍后重试」，弹窗不关
爬虫再次抓同一支架upsert_bracket 只覆盖 image_url / image_file / updated_at，不动 note
打包版（dist/）老 exe 不认识 note 列，但 SQLite 允许多余列，读旧字段不受影响；下次重新打包才带上新功能

8 对照与备选

能力现状改后
支架图片只能去「新增支架」页输入同号间接改本页弹窗直接改（多图 / 封面 / 删除）
支架备注不存在新增字段，左卡显示，弹窗编辑
支架号只读只读（用户明确不改号）
新增适配记录只能去「新增支架」页勾选已有车型本页弹窗从字典勾选已有车型（不新建字典）
修改 / 删除适配记录行内「编辑 / 删除」+ 弹窗不变

未采用的方案

  • B 只做图片管理：号打错的场景仍无解；用户还要备注与新增车型，收益不够。
  • C 表格就地双击编辑：要改 models.py 的 DictTableModel 与 delegates.py，与现有「编辑 / 删除」链接交互重复，回归面最大。
  • 改支架号（级联重命名）：用户明确否决；且已落盘文件名 bracket_<id>_NN.jpg 不会跟着改，会出现「号变了、图名还是旧号」的长期脏数据。
  • 左卡多图轮播（大图翻页）：左卡只有 268 × 240，轮播控件会挤压备注与按钮区， 多图统一进弹窗看。

9 实施状态

v1.1（2026-10-28）已实施：brackets.note 迁移、save_bracket_meta()、 「编辑支架」与「添加车型」两个弹窗、左卡备注与按钮组均已上线。 按用户纠正，「添加车型」弹窗改为只勾选库里已有车型（FitmentPickDialog）， 不再支持手输新建品牌 / 车型。设计稿中的尺寸与配色为近似预览，实际以 QSS token 为准。
