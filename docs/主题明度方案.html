0. 怎么用这份稿

下面每套方案都给出「1:1 模拟窗口」：宽度按应用实际 1280px 等比缩到 1044px 展示（约 0.82 倍）， 控件层级、字号、间距与真实界面一致，只换配色。你看哪套顺眼，告我编号（A / B / C）即可，我再改 app/config.py 的 C 调色板并跑一次启动验证。

三套候选的定位：

方案定位和现状的距离
A 提亮深灰仍是深色主题，整体亮度上抬约一档，接近 VS Code「Dark+ 提亮版」/ Windows 10 深灰小改，观感熟悉
B 中性石墨明显的中灰，接近 GitHub Dark Dimmed、Windows 高对比关闭时的「浅灰面板」中改，亮不少
C 浅色真正的浅色主题（白底深字），接近 Windows 11 浅色模式 / Excel大改，完全换风格
说明：明亮（brighter）与浅色（light theme）是两件事。只想要「没那么黑」选 A；想「明显亮」选 B；想换成白底选 C。

6. 实现影响面（三套相同）

问题在于现在的颜色没有全部集中：config.C 只管了 12 个语义色，另有 5 处硬编码色写在 QSS 里、2 处写在 ui.py 里。要换亮度必须先把它们抽成变量，否则会出现「底色变了、斑马纹还是旧灰」的花斑问题。

位置现状计划
config.Cbg / panel / panel2 / card / border / text / dim / faint / accent / accent_bg …新增 input / alt_row / header / scroll / on_accent 五个键，随方案取值
theme.py 输入框background: #1f1f1f改 @input
theme.py 表格斑马 / 表头 / 按钮 hover / 列表 hover#313131、#333333 ×3改 @alt_row、@header
theme.py 滚动条#4a4a4a、#5e5e5e改 @scroll、@scroll_hover
theme.py 选中文字#ffffff ×3改 @on_accent（浅色方案下用深字）
ui.py 图片占位底background:#1f1f1f ×2改 config.C["input"]
验证方式：改完用 QT_QPA_PLATFORM=offscreen 先跑一次构建自检，再由你确认后启动真实窗口截图对比（不自动改你桌面上正在运行的实例）。

7. 选择建议

你的感受建议
「就是有点闷，别太黑」A 提亮深灰：最稳，风险最小
「要明显亮，但晚上也别刺眼」B 中性石墨：推荐区间
「白天在办公室看不清，干脆白底」C 浅色
另外可选的折中做法：跟随系统（Windows 深/浅色自动切换），但要维护两套色值，工作量约为单套的 2 倍；如果你日常固定一台机器，不建议上。
